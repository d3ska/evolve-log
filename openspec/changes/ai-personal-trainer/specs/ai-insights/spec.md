## ADDED Requirements

### Requirement: Scheduled daily summary generation
The system SHALL generate a daily training summary at 02:00 each night using `@Scheduled(cron = "0 0 2 * * *")`. The job SHALL use the Haiku model, retrieve training activity for the past 24 hours, and store the result in the `ai_insights` table with `type = 'DAILY_SUMMARY'`.

#### Scenario: Daily summary stored for active day
- **WHEN** the nightly scheduler runs and the user had at least one workout in the past 24 hours
- **THEN** a new row is inserted into `ai_insights` with `type = 'DAILY_SUMMARY'` and Markdown content generated by Haiku

#### Scenario: No insight generated for inactive day
- **WHEN** the nightly scheduler runs and the user had no workout activity in the past 24 hours
- **THEN** no `ai_insights` row is created for that day

### Requirement: Scheduled weekly report generation
The system SHALL generate a weekly training report every Monday at 03:00 using `@Scheduled(cron = "0 0 3 * * MON")`. The job SHALL use the Sonnet model, analyse the previous 7 days of training, and store the result in `ai_insights` with `type = 'WEEKLY_REPORT'`.

#### Scenario: Weekly report covers previous 7 days
- **WHEN** the Monday scheduler runs
- **THEN** a `WEEKLY_REPORT` insight is stored covering `period_start` = previous Monday and `period_end` = previous Sunday

#### Scenario: Duplicate report not created
- **WHEN** a weekly report for the same `(user_id, type, period_start)` already exists in `ai_insights`
- **THEN** the job skips generation and logs an `INFO` message; no duplicate row is inserted (enforced by `UNIQUE` constraint)

### Requirement: Insight content is AI-generated Markdown
The `content` column of `ai_insights` SHALL store Markdown text produced by the AI model. The content SHALL include structured sections such as sessions completed, volume summary, personal records achieved, and actionable suggestions.

#### Scenario: Content is valid Markdown
- **WHEN** an insight is generated
- **THEN** the `content` field contains non-empty Markdown text starting with a heading

### Requirement: Manual insight generation endpoint
The system SHALL expose `POST /api/ai/insights/generate` accepting `{ "type": "WEEKLY_REPORT" | "DAILY_SUMMARY" }`. This endpoint SHALL trigger on-demand generation for the current period and return the generated insight ID. The endpoint SHALL be authenticated.

#### Scenario: Manual trigger creates insight
- **WHEN** an authenticated user calls `POST /api/ai/insights/generate` with `{"type": "WEEKLY_REPORT"}`
- **THEN** the system generates a weekly report immediately and returns `{"id": "<uuid>", "type": "WEEKLY_REPORT"}`

### Requirement: Insight retrieval API
The system SHALL expose `GET /api/ai/insights?type=<TYPE>&limit=<N>` returning a list of stored insights ordered by `generated_at DESC`. The default limit SHALL be 4 and the maximum SHALL be 20. The response SHALL include `id`, `type`, `periodStart`, `periodEnd`, `content`, `modelUsed`, and `generatedAt`.

#### Scenario: Returns latest weekly reports
- **WHEN** an authenticated user calls `GET /api/ai/insights?type=WEEKLY_REPORT&limit=4`
- **THEN** the response contains up to 4 most recent weekly reports ordered newest first

### Requirement: Scheduler skips when no API key configured
The system SHALL check for the presence of a configured API key in `ai_settings` before running any scheduled generation. If no key is present, the scheduler SHALL log an `INFO` message and skip without throwing an exception.

#### Scenario: Graceful skip without API key
- **WHEN** the scheduler fires and no `ai_settings` row exists for the user
- **THEN** no AI call is made, no insight row is created, and the application continues normally

### Requirement: Insight generation failure logged at ERROR
The system SHALL catch all exceptions from AI provider calls during scheduled insight generation, log them at `ERROR` level with full context (user ID, insight type, error message), and continue to the next user without crashing the scheduler.

#### Scenario: AI call failure does not crash scheduler
- **WHEN** the Anthropic API returns an error during nightly insight generation
- **THEN** the exception is caught, logged at `ERROR` level, and the scheduler job completes without re-throwing
